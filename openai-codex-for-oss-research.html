OpenAI 6 个月套餐：Codex for Open Source

这是 OpenAI 面向开源维护者的申请制计划。核心依据是公开 GitHub 仓库、维护者身份和项目生态价值，不是 GitHub Student Developer Pack 的学生福利。

结论

真实存在，但不是人人可领

  • 官方页面写明：开源维护者可申请 API credits、6 个月 ChatGPT Pro with Codex，以及 Codex Security 条件访问。
  • 选中后可获得的 Pro 权益用于日常编码、问题分流、代码审查和维护者工作流。
  • OpenAI 滚动审核，提交申请不保证获批；项目影响力和活跃维护证据很关键。
入口

官方申请页

  • 项目介绍：developers.openai.com/community/codex-for-oss
  • 申请表：openai.com/form/codex-for-oss
  • 条款：Codex for Open Source Program Terms
权益
6 个月 ChatGPT Pro，包含 Codex 使用
可选权益
API credits 用于 PR review、维护自动化、发布流程等 OSS 核心工作
筛选重点
维护证据 stars、下载量、issue/PR、release、生态重要性
申请材料

表单会要求这些信息

  • 姓名、与 ChatGPT 账号关联的邮箱。
  • GitHub username，需要设置为公开可见。
  • GitHub repository URL，仓库需要公开。
  • 说明你是 primary maintainer 还是 core maintainer。
  • 解释项目为什么符合条件，例如 GitHub stars、月下载量、生态价值。
  • OpenAI Organization ID，以及你如何使用 API credits。
注意事项

别踩这几个坑

  • 权益个人、限时、不可转让，也不能出售或共享。
  • OpenAI 可能要求验证身份、仓库归属、维护者状态或控制权。
  • 不要提交机密信息；条款明确申请材料不按保密材料处理。
  • Codex Security/API credits 可能需要额外审核。
建议路径

提高通过率的准备顺序

把 GitHub 个人资料和目标仓库设为 public，确认 README、license、release、贡献指南齐全。
整理项目数据：stars、forks、downloads、npm/PyPI/NuGet 等包下载量、活跃用户或被依赖情况。
列出维护证据：近期 PR review、issue triage、release 记录、安全修复、核心贡献提交。
用 500 字符内写清项目生态价值，再用 500 字符内写清 API credits 的实际用法。
研究时间：2026-05-31。资料来自 OpenAI 官方开发者页面、官方申请表、官方项目条款，以及 GitHub Education 官方页面核对。
